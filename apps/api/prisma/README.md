# prisma

## Overview

PostgreSQL Prisma schema defines identity, content, assessments, journeys, mentoring, community, notifications, feedback and audit persistence with prisma-client-js generation [schema.prisma:client] [schema.prisma:db].

## Invariants

- User email and username are unique; User.dob is nullable @db.Date. AuthAccount is unique by provider/providerAccountId; Session, VerificationToken and Invitation token fields are unique. UserRole, UserCapability and UserFollow use composite primary keys; UserConsent is unique by user/documentKey/version [schema.prisma:User] [schema.prisma:AuthAccount] [schema.prisma:Session] [schema.prisma:VerificationToken] [schema.prisma:Invitation] [schema.prisma:UserRole] [schema.prisma:UserCapability] [schema.prisma:UserFollow] [schema.prisma:UserConsent].
- Virtue, Subvirtue and Weakness nameEn are individually unique; WeaknessSubvirtue and ExposureWeakness/ResolutionWeakness/ChallengeWeakness use pair composite keys; TestAnswer is unique by testAttemptId/sentenceId. score is Int with a documented 1–4 meaning, without a declarative range check [schema.prisma:Virtue] [schema.prisma:Subvirtue] [schema.prisma:Weakness] [schema.prisma:WeaknessSubvirtue] [schema.prisma:ExposureWeakness] [schema.prisma:ResolutionWeakness] [schema.prisma:ChallengeWeakness] [schema.prisma:TestAnswer].
- Journey defaults to NOT_STARTED with exposure/resolution thresholds 1; JourneyWeakness has composite journey/weakness primary key. A schema comment documents a migration-owned partial unique live-journey index, absent from declarative Prisma attributes. VM relationships default PENDING. Journey ERC status defaults NOT_STARTED and custom/deactivated default false; each optional VmSidenote ERC foreign key is individually unique [schema.prisma:Journey] [schema.prisma:JourneyWeakness] [schema.prisma:VmRelationship] [schema.prisma:JourneyVmAssignment] [schema.prisma:JourneyExposure] [schema.prisma:JourneyResolution] [schema.prisma:JourneyChallenge] [schema.prisma:VmSidenote].
- ExperienceLog defaults visibility ONLY_ME, draft true and featured false; Blog defaults draft true and featured false; Upload defaults purpose EXPERIENCE. ChatMessage roomId/seqNo has a nonunique index. CustomErcReview.status and journey ERC reviewStatus fields are strings, and CustomErcReview optional target fields have no exactly-one constraint in this schema [schema.prisma:ExperienceLog] [schema.prisma:Blog] [schema.prisma:Upload] [schema.prisma:ChatMessage] [schema.prisma:CustomErcReview] [schema.prisma:JourneyExposure] [schema.prisma:JourneyResolution] [schema.prisma:JourneyChallenge].
- PothiSection.sectionNumber, ShlokaSchedule.scheduledDate (@db.Date), ShlokaQueueItem.position and CmsPage.key are unique; PothiSectionShloka has composite section/shloka primary key. CmsPage.version defaults 1, without automatic bumping. FeedbackUpvote is unique by item/user; FeedbackItem and ContentSuggestion default status NEW [schema.prisma:PothiSection] [schema.prisma:ShlokaSchedule] [schema.prisma:ShlokaQueueItem] [schema.prisma:CmsPage] [schema.prisma:PothiSectionShloka] [schema.prisma:FeedbackUpvote] [schema.prisma:FeedbackItem] [schema.prisma:ContentSuggestion].
- Role values are VRATARTHI/VRATMITRA/MODERATOR/ADMIN; Capability values FEEDBACK_WIDGET/CONTENT_EDIT/CONTENT_SUGGEST/PRODUCT_DOCS_VIEW; JourneyState values NOT_STARTED/ACTIVE/PAUSED/DORMANT/COMPLETED; ErcStatus values NOT_STARTED/IN_PROGRESS/SUBMITTED/APPROVED/REVISIT; ExperienceVisibility values ONLY_ME/FRIENDS/PUBLIC; SuggestionStatus distinguishes ACCEPTED from SHIPPED [schema.prisma:Role] [schema.prisma:Capability] [schema.prisma:JourneyState] [schema.prisma:ErcStatus] [schema.prisma:ExperienceVisibility] [schema.prisma:SuggestionStatus].

## Side Effects

- Declared user deletion cascades remove roles, capabilities, consents, follows, auth accounts, sessions, verification tokens, recipient notifications, feedback items/upvotes and authored suggestions [schema.prisma:UserRole] [schema.prisma:UserCapability] [schema.prisma:UserConsent] [schema.prisma:UserFollow] [schema.prisma:AuthAccount] [schema.prisma:Session] [schema.prisma:VerificationToken] [schema.prisma:Notification] [schema.prisma:FeedbackItem] [schema.prisma:FeedbackUpvote] [schema.prisma:ContentSuggestion].
- Declared cascades remove weakness/subvirtue links, ERC/weakness links, assessment answers, journey weakness/VM/ERC children and resolution checkins when their owning records are deleted [schema.prisma:WeaknessSubvirtue] [schema.prisma:ExposureWeakness] [schema.prisma:ResolutionWeakness] [schema.prisma:ChallengeWeakness] [schema.prisma:TestAnswer] [schema.prisma:JourneyWeakness] [schema.prisma:JourneyVmAssignment] [schema.prisma:JourneyExposure] [schema.prisma:JourneyResolution] [schema.prisma:JourneyChallenge] [schema.prisma:ResolutionCheckin].
- Declared cascades remove experience/shloka/resource tags, blog comments, Pothi section links and feedback upvotes with their owners; deleting an experience log sets Upload.experienceLogId null [schema.prisma:ExperienceLogTag] [schema.prisma:ShlokaTag] [schema.prisma:ResourceTag] [schema.prisma:BlogComment] [schema.prisma:PothiSectionShloka] [schema.prisma:FeedbackUpvote] [schema.prisma:Upload].

## Verification

From the repository root:

```sh
pnpm --filter api test:unit
```

The [`test:unit`](./../package.json) script runs `vitest run --project unit`. This is a package-level check; these documentation changes did not run it.

Unit tests do not apply these SQL migrations or validate a deployed database. Migration scripts are historical changes; the current schema is defined in `apps/api/prisma/schema.prisma`.
