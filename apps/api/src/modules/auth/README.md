# auth

## Overview

Authentication HTTP flows and persistence, with Passport, email, session guards and signup expiry cleanup. AuthModule exports AuthService, SessionGuard and OptionalSessionGuard. [auth.module.ts:AuthModule] [auth.controller.ts:AuthController] [auth.repository.ts:AuthRepository]

## Interface

- AuthController declares POST auth/register, login, logout, forgot-password, resend-verification, reset-password, verify-email, request-email-change, confirm-email-change, link-google, google/signup, complete-onboarding, complete-framework and consents/accept. [auth.controller.ts:AuthController]
- AuthController declares GET auth/google, google/callback, check-username, csrf, me, product-docs-access and consents/outstanding; it injects local AuthService and cross-module CapabilitiesService alongside ConfigService. [auth.controller.ts:AuthController]
- AuthRepository exposes user/email/username/account lookup and creation, email/password/account updates, identity release, pending signup, policy/consent and onboarding operations. [auth.repository.ts:AuthRepository]
- AuthRepository exposes session creation/lookup/activity/deletion/reauthentication and verification-token creation/lookup/use/invalidation operations, backed by PrismaService. [auth.repository.ts:AuthRepository.createSession] [auth.repository.ts:AuthRepository.createVerificationToken]
- Consent API: outstandingConsents(userId) returns current unaccepted policy versions; acceptOutstandingConsents(userId) records and returns them. [auth.service.ts:outstandingConsents] [auth.service.ts:acceptOutstandingConsents]
- register(email,password,displayName,username,dob,consents,language?) returns user and verificationEmailSent; login(email,password,ip,userAgent) returns AuthResult. [auth.service.ts:register] [auth.service.ts:login]
- startGoogleSignup(username,dob,consents,language?) returns pendingId; handleGoogleLogin(profile,ip,userAgent,pendingSignupId?) returns AuthResult or link_pending token; linkGoogleAccount(token,password,ip,userAgent) returns AuthResult. [auth.service.ts:startGoogleSignup] [auth.service.ts:handleGoogleLogin] [auth.service.ts:linkGoogleAccount]
- verifyEmail(token) returns user; resendVerification(email) returns sent; forgotPassword(email) returns exported ForgotPasswordOutcome=no_account|reset_sent|set_password_sent; resetPassword(token,newPassword) returns void; changePassword(userId,currentPassword,newPassword) returns replacement sessionToken. [auth.service.ts:verifyEmail] [auth.service.ts:resendVerification] [auth.service.ts:ForgotPasswordOutcome] [auth.service.ts:resetPassword] [auth.service.ts:changePassword]
- verifyPassword returns boolean; assertRecentlyAuthenticated(userId,sessionId,password?) gates sensitive actions; reauthenticateWithGoogle returns boolean; markSessionReauthenticated stamps a session. [auth.service.ts:verifyPassword] [auth.service.ts:assertRecentlyAuthenticated] [auth.service.ts:reauthenticateWithGoogle] [auth.service.ts:markSessionReauthenticated]
- listConnectedAccounts returns provider/connectedAt plus hasPassword; disconnectAccount returns removed provider; requestEmailChange(userId,sessionId,newEmail,currentPassword?) returns sent; confirmEmailChange(token) returns user. [auth.service.ts:listConnectedAccounts] [auth.service.ts:disconnectAccount] [auth.service.ts:requestEmailChange] [auth.service.ts:confirmEmailChange]
- logout(token), forceLogout(userId), validateSession(token) returning user/sessionId or null, getCurrentUser(userId), completeOnboarding(userId,displayName?,username?,language?,gender?), completeFramework(userId), and checkUsernameAvailability(username) expose session/profile setup operations. [auth.service.ts:logout] [auth.service.ts:forceLogout] [auth.service.ts:validateSession] [auth.service.ts:getCurrentUser] [auth.service.ts:completeOnboarding] [auth.service.ts:completeFramework] [auth.service.ts:checkUsernameAvailability]
- checkLockout(email) returns locked/secondsRemaining; recordFailedLogin(email,ip?,userAgent?,reason?) and clearLockout(email) maintain lockout state; PendingSignupsCron.purgeExpired runs at cron 15 3 \* \* \*. [auth.service.ts:checkLockout] [auth.service.ts:recordFailedLogin] [auth.service.ts:clearLockout] [pending-signups.cron.ts:purgeExpired]
- [consent](./consent/README.md): Pure comparison of accepted consent versions against current policy versions.
- [decorators](./decorators/README.md): HTTP parameter decorators expose request user and session identity.
- [dto](./dto/README.md): Class-validator request contracts for registration, Google signup/linking, sign-in, recovery, email change and onboarding.
- [guards](./guards/README.md): Google Passport guard builds OAuth state and exports reauthentication state parser.
- [strategies](./strategies/README.md): Passport Google strategy converts provider profiles into application GoogleProfile values.
- [types](./types/README.md): Authentication contracts describe session identity, session creation, provider identity and authentication results.

## Invariants

- SessionGuard decorates logout, consent routes, email-change request, onboarding/framework, me and docs-access; GoogleOAuthGuard decorates Google routes; verify-email, confirm-email-change and link-google carry SkipCsrf. Login throttles identity at 20 and default at 100 per 900000 ms; several email/reset/signup operations use 5 per 3600000 ms and register uses registerThrottle(). [auth.controller.ts:AuthController]
- Google callback branches reauthentication before login handling, validates the existing cookie session for reauthentication, handles link_pending separately and chooses dashboard/onboarding by onboardingCompletedAt; docs access invokes capabilities.assertProductDocsView. [auth.controller.ts:AuthController.googleCallback] [auth.controller.ts:AuthController.productDocsAccess]
- User email/ID/username lookups filter deletedAt null; username lookup lowercases its input; user creation nests consent/account/VRATARTHI role writes, defaults language EN and links only PENDING invitations with null inviteeId. [auth.repository.ts:AuthRepository.findUserByEmail] [auth.repository.ts:AuthRepository.findUserByUsername] [auth.repository.ts:AuthRepository.createUserWithEmailAccount] [auth.repository.ts:AuthRepository.createUserWithOAuthAccount] [auth.repository.ts:AuthRepository.linkPendingInvitations]
- applyEmailChange transaction updates User.email, clears pendingEmail and updates EMAIL provider IDs; consumePendingSignup attempts deletion before expiry evaluation and swallows deletion rejection; session proof consumption conditionally clears timestamps >= notBefore and returns count > 0; verification lookup requires matching type and usedAt null. [auth.repository.ts:AuthRepository.applyEmailChange] [auth.repository.ts:AuthRepository.consumePendingSignup] [auth.repository.ts:AuthRepository.consumeSessionReauthentication] [auth.repository.ts:AuthRepository.findVerificationToken]
- Registration normalizes email and rejects invalid/underage DOB before duplicate-email lookup; consent resolution deduplicates keys, rejects unknown documents and uses database versions instead of claimed versions. [auth.service.ts:register] [auth.service.ts:resolveConsents]
- Credential login normalizes email before lockout lookup, rejects missing account/password or invalid password, then unverified/suspended users; successful login clears lockout. Password hashing uses 12 bcrypt rounds; generated tokens are 32 random bytes encoded as hex. [auth.service.ts:login] [auth.service.ts:BCRYPT_ROUNDS] [auth.service.ts:generateToken]
- Google signup validates DOB and username availability before storing a 15-minute pending record. Only the new-user branch consumes pending signup and rechecks age; it sets emailVerifiedAt without checking profile.emailVerified. An existing deleted Google identity is released only when pendingSignupId is present, otherwise AccountDeletedException; suspended existing Google users are rejected. Chosen username collisions get numbered variants then random suffix. [auth.service.ts:startGoogleSignup] [auth.service.ts:PENDING_SIGNUP_TTL_MINUTES] [auth.service.ts:handleGoogleLogin] [auth.service.ts:claimUsername]
- Google linking requires unexpired GOOGLE_LINK token, valid credential password and object metadata with nonempty googleId; email is marked verified only for metadata.emailVerified===true. Email verification/link/reset/change tokens use their specific types and reject missing/expired tokens. Verification lifetime is 24 hours, reset/change 1 hour, Google link 15 minutes. [auth.service.ts:linkGoogleAccount] [auth.service.ts:verifyEmail] [auth.service.ts:resetPassword] [auth.service.ts:confirmEmailChange] [auth.service.ts:VERIFICATION_TOKEN_EXPIRY_HOURS] [auth.service.ts:PASSWORD_RESET_TOKEN_EXPIRY_HOURS] [auth.service.ts:GOOGLE_LINK_TOKEN_EXPIRY_MINUTES]
- Reauthentication accepts a valid current password or consumes session proof newer than 10 minutes, including when a supplied password is wrong. If neither succeeds, a supplied password produces PasswordIncorrectException and an absent password produces ReauthenticationRequiredException. Google reauthentication requires googleId owned by userId; markSessionReauthenticated explicitly requires caller to establish identity ownership. [auth.service.ts:assertRecentlyAuthenticated] [auth.service.ts:REAUTH_WINDOW_MINUTES] [auth.service.ts:reauthenticateWithGoogle] [auth.service.ts:markSessionReauthenticated]
- Disconnect refuses absent provider or removal of the last usable login method; EMAIL counts only with passwordHash. Email change requires recent authentication, normalized different address and no live claim; confirmation checks pending address against token metadata and rechecks both user-email occupancy and EMAIL account claim, releasing deleted owners' claims. [auth.service.ts:disconnectAccount] [auth.service.ts:requestEmailChange] [auth.service.ts:confirmEmailChange]
- Session validation rejects missing, expired, deleted-user or suspended-user sessions; accepted sessions extend expiry using SESSION_TTL_DAYS default 30. Onboarding account setup checks username uniqueness; framework completion is a separate step. Username availability accepts only lowercase letters, digits and underscores of length 3–30. [auth.service.ts:validateSession] [auth.service.ts:constructor] [auth.service.ts:completeOnboarding] [auth.service.ts:completeFramework] [auth.service.ts:USERNAME_REGEX]
- Failed-login threshold is 10; counter TTL initially 3600 seconds and lock duration/TTL 900 seconds. Redis errors and corrupt lockout timestamps fail open with warnings. Pending-signup cron only logs positive removal counts. [auth.service.ts:recordFailedLogin] [auth.service.ts:checkLockout] [auth.service.ts:LOCKOUT_MAX_FAILURES] [auth.service.ts:LOCKOUT_WINDOW_SECONDS] [auth.service.ts:LOCKOUT_DURATION_SECONDS] [pending-signups.cron.ts:purgeExpired]

## Side Effects

- Controller sets session cookies after login/linking/Google login, clears cookies on logout, invokes legacy-cookie cleanup and redirects Google callback responses for session, linking, onboarding and error outcomes; cookie options come from local common/http/cookie helpers. [auth.controller.ts:AuthController.setSessionCookie] [auth.controller.ts:AuthController.clearSessionCookie] [auth.controller.ts:AuthController.googleCallback]
- Audited metadata records logout, consent acceptance, password-reset request/change, verification resend and email-change request/confirmation actions, including selected request email metadata. [auth.controller.ts:AuthController.acceptConsents] [auth.controller.ts:AuthController.logout] [auth.controller.ts:AuthController.forgotPassword] [auth.controller.ts:AuthController.resendVerification] [auth.controller.ts:AuthController.resetPassword] [auth.controller.ts:AuthController.requestEmailChange] [auth.controller.ts:AuthController.confirmEmailChange]
- Repository reads/writes users, auth accounts, invitations, pending signups, CMS policy versions and user consent rows, including identity-claim deletion, expired signup deletion and profile/setup timestamps. [auth.repository.ts:AuthRepository]
- Repository creates, reads, updates and deletes session rows and creates/reads/marks verification tokens used, including metadata, IP/user agent, activity/expiry and reauthentication timestamps. [auth.repository.ts:AuthRepository.createSession] [auth.repository.ts:AuthRepository.updateSessionActivity] [auth.repository.ts:AuthRepository.createVerificationToken] [auth.repository.ts:AuthRepository.invalidateTokensByUserAndType]
- Consent methods read accepted/current versions and append consent records through AuthRepository; register reads identity claims, releases deleted claims, persists user/email account, consents and verification token. [auth.service.ts:outstandingConsents] [auth.service.ts:acceptOutstandingConsents] [auth.service.ts:register]
- register renders and sends transactional verification email; send failure changes verificationEmailSent to false and logs userId/email/error after account creation. resendVerification reads user/accounts, invalidates prior verification tokens, creates a new token and sends rendered mail. [auth.service.ts:register] [auth.service.ts:resendVerification]
- Google flows read accounts/users, create or consume pending signup, release identity claims, invalidate/create GOOGLE_LINK tokens or create OAuth user/account, and persist sessions; linking adds OAuth account, marks token used and may mark email verified. [auth.service.ts:startGoogleSignup] [auth.service.ts:handleGoogleLogin] [auth.service.ts:linkGoogleAccount]
- forgotPassword reads user/email account, replaces reset tokens and sends rendered reset/set-password email. verifyEmail consumes token and verifies address. resetPassword updates or creates EMAIL password account, consumes token, verifies email and deletes all sessions; changePassword updates hash, deletes all sessions and creates replacement. [auth.service.ts:forgotPassword] [auth.service.ts:verifyEmail] [auth.service.ts:resetPassword] [auth.service.ts:changePassword]
- Reauthentication reads password/Google account and consumes or stamps session proof; connected-account listing reads accounts and disconnect deletes the chosen account. Email-change request reads users/claims, stores pending email, replaces EMAIL_CHANGE token and sends rendered confirmation mail; confirmation reads pending/token/claims, may release deleted claims, applies address change and consumes token. [auth.service.ts:verifyPassword] [auth.service.ts:assertRecentlyAuthenticated] [auth.service.ts:reauthenticateWithGoogle] [auth.service.ts:markSessionReauthenticated] [auth.service.ts:listConnectedAccounts] [auth.service.ts:disconnectAccount] [auth.service.ts:requestEmailChange] [auth.service.ts:confirmEmailChange]
- Session methods create/read/delete sessions and update accepted session activity/expiry; getCurrentUser and username helpers read users. completeOnboarding persists profile/setup state and fires usersIndex.upsert with isPublic=true; completeFramework persists onboarding completion. [auth.service.ts:createSession] [auth.service.ts:validateSession] [auth.service.ts:logout] [auth.service.ts:forceLogout] [auth.service.ts:getCurrentUser] [auth.service.ts:checkUsernameAvailability] [auth.service.ts:claimUsername] [auth.service.ts:generateUsername] [auth.service.ts:completeOnboarding] [auth.service.ts:completeFramework]
- Login records login_success/account_lockout audits; recordFailedLogin records login_failure and threshold account_lockout audits. Lockout helpers read/increment/write/expire/delete Redis lockout:<email> hashes and log Redis failures or corrupt timestamps. [auth.service.ts:login] [auth.service.ts:recordFailedLogin] [auth.service.ts:checkLockout] [auth.service.ts:clearLockout]
- Pending signup housekeeping deletes expired records through repository and logs count when positive. [pending-signups.cron.ts:purgeExpired]
